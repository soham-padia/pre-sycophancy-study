# _markdown/ — Team & Agent Communication Hub

This folder is the shared knowledge base for the team **and for each teammate's
Claude (or other AI assistant)**. If you are an AI assistant working in this
repo: **read this folder first**, in this order:

1. `README.md` (this file) — rules and conventions
2. `UTKARSH_START_HERE.md` — where the project stands as of Oct 24, 2026, and the current plan
3. `notes/` — one file per session note, newest first (`ls -t notes | head`)
4. `ONBOARDING.md` — data, scripts, pitfalls (superseded in part; `CLAUDE.md` and `docs/` win)
5. `AGENT_NOTES.md` — the session log up to Oct 24, 2026 (archive; new notes go to `notes/`)
6. `PAPER_STATUS.md`, `REVISION_TASKS.md` — the EACL/EMNLP-era tracking (historical)
7. `RESEARCH_SUMMARY.md` — full research description (superseded in part)
8. `JSPACE_PROPOSAL.md` — an earlier proposed next phase

## Rules

### 1. Branches, always
**Never commit directly to `main`.** Create a branch per track/task:

```
git checkout -b track3-figures        # or track1-writing, track4-sections, fix-<thing>
```

Push your branch and open a PR. `main` holds the state everyone's analyses
depend on — regenerated figures and CSVs on `main` must come from the scripts
in `analysis/`, never hand-edited.

### 2. Agent communication protocol
**From Oct 24, 2026: one new file per entry in `notes/`** (template in
`notes/README.md`). Two people appending to the same file conflicted in git; a
new file never does. Each person's Claude reads the notes newer than its own last
one at the start of a session. The rest of this section describes the archive.

`AGENT_NOTES.md` was an **append-only log**. At the end of any working session
that changed something, sessions appended an entry:

```markdown
## 2026-07-02 — <name or agent> (branch: track3-figures)
- What changed: ...
- Files touched: ...
- Blocked on / needs review: ...
- Handoff notes for next session: ...
```

Do not edit or delete previous entries. Read the log before starting work so
you don't redo or undo someone else's session.

### 3. Anonymization — read this or we get desk-rejected again
Our ARR submission was **desk-rejected** because the anonymous repo link
exposed author names (a leftover internal markdown file and a plot filename).
The anonymous link points at a snapshot of this repo. Therefore:

- **No personal names, emails, or institution names** in any tracked file
  outside `_markdown/` (code comments, filenames, plot labels included).
- `_markdown/` is team-internal and WILL contain names — that is fine for now,
  but **before creating the next anonymous submission link, we must create a
  fresh single-commit snapshot that excludes `_markdown/` entirely** (git
  history retains deleted files; a fresh history is the only safe option).
- If you add a file with a name in it anywhere else, you are the reason we
  get desk-rejected twice.

### 4. Figures and the paper
The paper lives in **Overleaf** (not in this repo). Figures are generated by
`analysis/plot_*.py` into `analysis_claude/` and must be manually uploaded to
Overleaf's `new_figures/` folder. If you regenerate a figure, note it in
`AGENT_NOTES.md` so whoever syncs Overleaf knows.
